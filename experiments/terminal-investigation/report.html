Ember Deck terminal study

Which terminal should the panel UI run in, can it show different text sizes inside the existing Textual app, and what could the Scope page become? Everything here was checked against the code, upstream sources and real Textual output; what only the Pi can prove is marked as such.

13 Nov 2026branch feature/ui-layout-rework @ 4fd09ffTextual 8.2.7 · Rich 15.0.0proofs of concept: experiments/terminal-investigation/
Recommendation

Move the panel to kitty, keep Textual, and add two small custom pieces, after a one-evening Pi validation.

  • kitty is the only candidate that both draws larger text (its OSC 66 text-sizing protocol) and shows pixel graphics in a way Textual can live with (Unicode image placeholders). It is packaged in Debian Trixie (0.41.1, arm64) and, per its source, needs only OpenGL 3.1 on Linux, which the Pi 5 driver exposes.
  • Mixed font sizes work in Textual only through a driver filter: widgets draw placeholder characters and a ~60-line subclass of Textual's Linux driver turns them into kitty large-text sequences. Against Textual's real output and a model of kitty's rules it survived every redraw case tried (0 errors); the obvious approach failed (52 misplaced cells).
  • The Scope page can become a pixel visualiser from data Echo already publishes, with Textual's text untouched while it animates.
  • Do one thing now, in any terminal: the eighth-block spectrum (section 5) is a large improvement over today's scope and works in LXTerminal.
  • If kitty fails on the Pi, stay on LXTerminal (option A) and keep the dot-matrix lyrics. A native graphics UI is not justified by anything found here.

Mixed font sizes: feasible in kitty, through a driver filter

kitty's protocol draws text at s times normal size as a block s cells tall. Two rules from its spec decide how Textual can use it: overwriting a cell on the block's top row erases the block, and printing on a lower row makes the cursor skip past the block first. Textual redraws a changed widget by moving the cursor to the start of each row and writing the full width (captured from Textual 8.2.7), so printing spaces under large text pushes the rest of that row sideways.

Textual also cannot carry the escape itself: in the captured output Rich strips the BEL that ends the sequence, and Textual counts the escape's bytes as visible cells. The working design keeps the escape out of Textual altogether:

  1. A widget draws private-use placeholder characters, one per cell the large text will cover: an anchor at the top-left, then skip markers.
  2. A subclass of Textual's LinuxDriver rewrites the output: the anchor becomes the OSC 66 sequence, top-row skips vanish (kitty's cursor already moved), lower-row skips become cursor-forward moves.

Replaying Textual's real output for a first frame, longer and shorter large lines, a neighbour updating on the block's lower row, an unrelated update, a full repaint, and hiding and showing the widget into a model of kitty's rules gave 0 mismatches. Printing spaces under the block gave 52. The model follows the spec, not kitty itself; kitty_textsize_demo.py is the real test.

Limits: whole-cell scales (1–7, plus fractions such as 1.5 rendered inside a 2 × 2 block); the app wraps lines itself; nothing may be drawn on top of a large block; support has to be detected before Textual starts (kitty's CPR method, in pi_probe.py), with normal text as the fallback.

Visualiser opportunities

Every image is the real Scope page at 640 × 480 (Textual layout from the current branch) with the panel's contents drawn from real audio: the "Tech Demo" video's soundtrack, a camera recording of the Deck playing, put through Echo's exact processing. It reads quieter than Echo's line-level input would. The kitty images are composited where kitty would draw them.

Data available now
  • Spectrum: 1025 bins, 23.4 Hz apart, 50 per second. Enough for bars, peak hold, spectrograms and radial forms. Bass detail is coarse: below 100 Hz there are four bins.
  • Waveform: 160 samples covering 42.7 ms, mono, no trigger, so traces wander frame to frame.
  • The UI only reads shared memory: no new capture and no effect on playback or on Foxfire.
Would need Echo changes
  • Stereo or left/right displays: Echo mixes to mono before publishing; it would publish per-channel data.
  • A steady oscilloscope: publish the raw 2048-sample window, or trigger on a zero crossing in Echo.
  • Finer bass: a larger FFT, at the cost of latency.
  • Every source: depends on what Echo captures (Pi check 1).

Recommended terminal and rendering strategy

  1. Terminal: kitty, subject to the Pi checklist. It is the only candidate with both capabilities, packaged for the Deck's OS, and its OpenGL requirement matches what the Pi 5 driver exposes (checked in kitty's source, which overrides older reports quoting 3.3).
  2. Keep Textual and compute_layout(). Add the placeholder driver filter for large text and a placeholder image widget for the visualiser and cover.
  3. Detect, then fall back. At start, probe for OSC 66 scaling and kitty graphics. Without them, the same UI runs as today: normal text and the eighth-block visualiser. LXTerminal stays a working fallback.
  4. Fonts and grid: decide after the probe. The likely shape is a small base font (about 8 × 16 px, 80 × 30) for dense logs and track details, with 2× text where reading distance matters. pi_probe.py reports the real cell size for each font size.

What this means for the UI

Now Playing
  • Title at 2× (two lines), artist at 1.5×, album and progress at 1×.
  • Current lyric at 2× in a real font; neighbours at 1×.
  • Cover as pixels at about 224 px. Needs Minstrel to publish a larger cover (it already fetches one); today's 48 × 48 only scales smoothly.
  • Header keeps track context and format, no repeats.
Scope
  • Give the visualiser the whole body; keep one compact track line and the lyric band.
  • Start with peak-hold bars or the spectrogram; both are cheap.
  • Radial "art mode" is a candidate second style.
Console
  • Keep the full-width log, the newest-line fix and the seven-worker heartbeat strip.
  • Readability comes from kitty's crisper rendering and the font choice, not large text: logs need columns.
  • Optionally the heartbeat strip at 1.5×.
Track Info
  • Title at 2× across the top; two columns of known fields below (unknown fields are already hidden).
Dot-matrix lyrics

Superseded if kitty passes: real 2× text keeps lowercase and fits more per line (36 against 25 characters). Keep it until the migration is confirmed, then remove it. If the Deck stays on LXTerminal, it remains the best available large text.

compute_layout()

Keep it as the one place geometry lives, but design for the Deck's single grid once the font is chosen. Keep only a minimal fallback for desktop testing, and pin the tests to the Deck's grid instead of sweeping 40 × 18 to 100 × 60.

Pi validation checklist

Commands and pass criteria are in experiments/terminal-investigation/README.md. Installing kitty is the only system change; it is yours to make.

  1. Record OS release, panel output mode (wlr-randr), OpenGL version and renderer (glxinfo -B), Echo's default source.
  2. Run pi_probe.py in the current LXTerminal profile: record the grid and cell size, photograph the samples.
  3. Run pi_probe.py in kitty full screen at font sizes 8–11: all four capabilities should report true; photograph large-text lines.
  4. Run kitty_textsize_demo.py for 10 minutes, pressing r and h: no fragments, no sideways shifts, no flicker.
  5. Run kitty_graphics_demo.py with music playing, in both update modes, both media and all styles: note fps, process and kitty CPU, flicker.
  6. Run visualisers.py: renderer timings on the Pi.
  7. Run kitty and the Firefox kiosk together for an hour: no audio dropouts, flat memory, normal temperature.
  8. Confirm the panel window lands on the 5.6-inch output under Labwc when launched as kitty (window rule by title or class).
